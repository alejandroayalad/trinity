## How to read the requirements

- Source of truth: `docs/design-reference/2026-10-04-explorer-handoff/Trinity.dc.html` (cited as "line N"), its README and screenshots 01–18. Secondary: `docs/design-reference/2026-10-04/`.
- Colors are written as token names from `frontend/src/styles/tokens.css`. Each named token has the same hex value as the prototype. A value with no token is written as a raw number; design.md decides whether it becomes a token.
- "Short ID" means R21: first 8 characters, mono, full value in a tooltip. Day formats: `D Mon YYYY` (`formatDay`), `D Mon` (`formatShortDay`), range `D Mon – D Mon YYYY` (`formatDayRange`) from `frontend/src/lib/dates.ts`. Times: `D Mon YYYY, HH:mm UTC` (R19).
- Quoted text is exact copy. `{x}` is a value from the API.
- Every visible prototype string for these screens is in a requirement below or in the differences table.

## Requirements

### UF-B — Base styles (slice V1)

| ID | Requirement |
|---|---|
| UF-B01 | Global stylesheets (`app.css`, `base.css`) contain no element-type rule for `label`, `input`, `select`, `textarea`, `table`, `th`, `td` or `h2`. Only the resets in `base.css` stay (box-sizing, margins, `font: inherit`, link color, focus outline) plus one heading reset, `h1, h2, h3 { font-weight: 600; line-height: 1.2 }` (design.md §1). Sizes stay in modules. A checkbox or radio is never forced to 40px height. |
| UF-B02 | The page background (`html`, `body`) and the sidebar are `--color-bg`. The main column is `--color-surface` (line 14, 70, 114). No `.panel` card wraps page blocks; content is grouped by 1px `--color-border` top rules and spacing (README "Spacing"). Cards exist only where the prototype has one: sign-in card, selected-observation panel, refresh summary strip, candidate card, editor, schema aside, scroll tables, dialogs. |
| UF-B03 | The page content area has `padding: 32px`, `width: 100%`, `max-width: 1248px` (`--content-max`) and is left-aligned, not centered (line 136). Below 960px, the padding stays 32px at 924px; at 320–480px it may drop to 16px. |
| UF-B04 | A section rule is `margin-top: 40px; border-top: 1px solid --color-border; padding-top: 24px` (line 186, 311). The first section under a page header uses `margin-top: 32px` (line 160). |
| UF-B05 | Page title (h1): 32px (`--text-title`), weight 600, `--tracking-title`, line-height 1.15, color `--color-ink` (line 150). Subtitle: 15px (`--text-lg`), `--color-muted`, `margin-top: 6px` (line 151). Section title (h2): 19px (`--text-h2`), weight 600, `--tracking-h2` (line 188). |
| UF-B06 | The shell and every page use their own CSS Module (`*.module.css`) next to the component. Shared helpers stay in `base.css`. CSS Modules use tokens only; no raw hex (R03). `app.css` keeps no page or shell layout rules. |
| UF-B07 | Existing components are used where the prototype has the pattern: `Segmented`, `Tabs`, `Switch`, `Field`, `Callout`, `StatusBadge` (default and large), `Tag`, `TextLink`, `TextButton`, `EmptyState`, `UnavailableValue`, `Dialog`, `Toast`. `ToastProvider` is mounted once in the app root. Dates use the `lib/dates.ts` helpers; no page shows a raw `YYYY-MM-DD` or ISO timestamp. |
| UF-B08 | Buttons: primary = `--color-orange` background, 1px `--color-orange-border`, `--color-ink` text, weight 600, hover `--color-orange-hover`; secondary = `--color-surface`, 1px `--color-field-border`, hover border `--color-slate`; disabled opacity .45 with `cursor: not-allowed` (README "Components", line 46, 143, 307). All controls use `--transition-control` (160ms). |
